Halo, Semester 2!

Hari ini kita akan mengenal variabel. Variabel membantu Scratch mengingat sebuah nilai, misalnya Saldo, Skor, atau Nyawa. Di game Kliker Celengan, variabel yang akan kita pakai bernama Saldo.

Kita akan membuat aturan yang mudah diuji: saat bendera hijau ditekan, Saldo dimulai dari 0. Setiap kali sprite celengan diklik, Saldo bertambah 10. Celengan juga akan membesar sebentar, lalu kembali ke ukuran semula.

Gunakan angka dalam permainan sebagai simulasi, bukan jumlah uang tabungan asli. Simpan project sebagai file .sb3 dan kumpulkan melalui LMS. Sesi ini berdurasi 60 menit.

Bukan cuma membuat tampilan

Kamu akan belajar cara kerja game, bukan hanya mengganti gambar. Perhatikan hubungan antara aksi, blok kode, dan hasil yang terlihat.

Hasil minimal: sprite Bowl yang diklik menambah Saldo sebanyak 10. Saat bendera hijau ditekan lagi, Saldo kembali ke 0. Supaya pemain tahu kliknya berhasil, tambahkan suara atau animasi membesar-mengecil.

Di akhir sesi, kamu harus menguji hasilnya sendiri dan menyimpan file Scratch. Kalau salah satu hasilnya belum sesuai, gunakan halaman Detektif Code untuk mencari blok yang keliru.

Cek sebelum coding

Buka Scratch → File → Load from your computer jika kamu memakai Scratch Desktop atau editor yang menyediakan fitur memuat file lokal. Pilih starter Sesi 25, bukan proyek contoh yang sudah selesai.

Di starter sudah ada sprite Bowl sebagai celengan dan sprite koin 1 sebagai gambar koin, serta variabel Saldo. Jadi, kamu tidak perlu membuat semuanya dari awal. Jika monitor Saldo belum terlihat, centang kotak Saldo pada kategori Variables.

Kita cukup memakai angka latihan. Angka permainan adalah alat untuk memahami cara program menyimpan dan mengubah nilai; jangan gunakan data keuangan pribadi.

Dari cerita ke kode

Bayangkan Kiko mendapatkan koin hari ini, besok, dan lusa. Ia ingin mengetahui berapa tabungan yang sudah terkumpul. Dalam permainan Scratch, kita bisa memakai variabel Saldo untuk mengingat jumlah tersebut.

Ketika pemain menekan celengan, kode akan mengubah angka Saldo. Scratch lalu menampilkan angka terbaru lewat monitor variabel di Stage. Dengan begitu, Kiko tidak perlu menghitung koin dari gambar satu per satu.

Cerita ini mengingatkan kita bahwa menabung sedikit demi sedikit bisa membuat jumlah tabungan bertambah. Namun, game ini hanya simulasi, bukan alat pencatat uang yang tersimpan selamanya.

Memori kecil di dalam game

Variabel adalah nama untuk sebuah tempat penyimpanan nilai saat program berjalan. Pada game kita, namanya Saldo. Kalau Saldo bernilai 10 kemudian bertambah 10, nilai barunya menjadi 20.

Variabel tidak harus selalu untuk uang. Game lain bisa memakai variabel Nyawa untuk jumlah kesempatan, atau Skor untuk poin. Walaupun namanya berbeda, cara berpikirnya sama: Scratch mengingat kondisi terbaru dari permainan.

Anggap variabel seperti kotak dengan label. Kita bisa melihat isi kotaknya, menggantinya, atau menambah nilainya. Nanti kamu akan memakai dua blok Variables: set dan change.

Kapan menggunakan set dan change?

Blok set [Saldo] to (10) berarti: “mulai sekarang nilai Saldo tepat 10.” Jika dipakai lagi, hasilnya tetap 10. Inilah sebabnya blok set cocok untuk memberi nilai awal, misalnya set Saldo to 0.

Blok change [Saldo] by (10) berbeda. Scratch mengambil nilai yang sudah ada, lalu menambahkan 10. Misalnya Saldo 0 menjadi 10, lalu 20, kemudian 30.

Untuk Kliker Celengan, kita memakai set saat bendera hijau dan change saat celengan diklik. Salah memilihnya bisa membuat Saldo tidak bertambah meski tombol diklik berkali-kali.

Kenali tujuan sebelum memilih blok

Pertama tanyakan: apakah kita ingin menentukan angka baru, atau mengubah angka yang sudah ada? Jika ingin mengulang game dari awal, nilainya harus ditentukan dengan set Saldo to 0.

Jika pemain menabung lagi, angka baru harus dihitung dari Saldo terakhir. Gunakan change Saldo by 10. Tidak perlu membuat variabel baru setiap kali klik.

Latihan ini penting karena penampilan bloknya mirip—keduanya berwarna oranye dan berada di kategori Variables—tetapi hasilnya tidak sama.

Hitung satu per satu

Dalam latihan ini, Saldo awal bernilai Rp50.000. Kiko membeli buku seharga Rp15.000 sehingga tersisa Rp35.000. Setelah mendapat tambahan Rp10.000, saldonya menjadi Rp45.000. Setelah membeli alat tulis Rp5.000, saldo akhir adalah Rp40.000.

Perhatikan tanda + dan −. Tanda plus menambah nilai sebelumnya, sedangkan minus mengurangi nilai sebelumnya. Ini sejalan dengan blok change pada Scratch; kita bisa memakai nilai positif untuk menambah dan nilai negatif untuk mengurangi.

Kerjakan perhitungan tanpa memasukkan informasi keuangan asli. Fokus latihan bukan besarnya uang, melainkan bagaimana angka berubah setelah setiap kejadian.

Angka di layar mengikuti kode

Pada simulasi ini, tombol bergambar Bowl mewakili event when this sprite clicked. Satu klik menambah 10 pada variabel Saldo. Kalau klik lima kali dari 0, hasilnya 50.

Tombol bendera hijau mengulang kondisi awal: Saldo kembali ke 0. Ini mencontohkan script when green flag clicked yang akan kamu buat di Scratch.

Kamu juga bisa mencoba tombol “Coba bug: set to 10”. Tombol itu menunjukkan apa yang terjadi kalau kita mengganti angka Saldo menjadi 10, bukan menambahkannya. Latihan di halaman ini hanya simulasi; nantinya kamu tetap harus menyusun Blocks pada proyek .sb3.

Green Flag bukan hanya tombol jalankan

Bendera hijau biasanya digunakan untuk memulai game dari kondisi awal. Agar hasil pengujian selalu konsisten, script di bawah when green flag clicked perlu mengatur ulang nilai penting. Dalam Kliker Celengan, nilai itu adalah Saldo.

Kalau tidak ada set Saldo to 0, nilai yang tersisa dari percobaan sebelumnya bisa tetap terlihat. Ini membuat kita sulit membedakan sebuah permainan baru dengan percobaan sebelumnya.

Selain Saldo, sprite Bowl juga dikembalikan ke posisi x: 0, y: -20 dan ukuran 100%. Dengan begitu, gambar tidak terus membesar setelah kita menguji game berkali-kali.

Pilih sprite sebelum menyusun kode

Di Scratch, setiap sprite dapat memiliki script sendiri. Sprite yang dipilih terlihat pada panel sprite; Code Area menampilkan blok milik sprite tersebut.

Proyek starter memiliki sprite Bowl untuk celengan. Nama Bowl berasal dari aset di proyek yang diberikan, jadi jangan bingung jika gambarnya tampak seperti mangkuk atau celengan sederhana. Sprite koin 1 adalah gambar koin pendukung.

Stage merupakan tempat semua sprite dan backdrop terlihat. Monitor variabel Saldo juga tampil di Stage agar pemain bisa melihat angkanya. Sebelum menyusun blok, selalu cek nama sprite yang sedang aktif.

Starter bukan proyek yang sudah selesai

Kita memakai starter supaya tidak menghabiskan waktu membuat semua gambar dari awal. Di dalamnya sudah ada sprite Bowl, koin, beberapa backdrop, dan variabel Saldo. Yang belum ada adalah script yang membuat game bekerja.

Perhatikan bahwa sprite Bowl di starter hanya memiliki suara Pop. Pada contoh proyek guru, suara yang digunakan bernama Coin. Kamu bisa menambahkan suara Coin melalui tab Sounds → Choose a Sound. Jika belum sempat, pakai suara yang tersedia terlebih dahulu agar fitur klik dan Saldo tetap bisa diuji.

Variabel Saldo sudah tersedia. Jika namanya ada, jangan membuat Saldo kedua karena dapat menyebabkan kebingungan saat memilih blok.

Flowchart membantu menyusun urutan

Flowchart adalah gambar sederhana untuk menunjukkan urutan langkah program. Mulai dari Green Flag, Scratch menentukan nilai awal Saldo. Setelah itu, Scratch menunggu pemain mengklik Bowl.

Setiap klik menjadi sebuah event. Saat event terjadi, kode menambah Saldo 10 dan menjalankan suara serta efek ukuran. Klik berikutnya menjalankan kode yang sama, sehingga nilai terus bertambah.

Dengan menggambar alur dulu, kamu lebih mudah memilih Blocks di Scratch. Event ada di kategori Events, perubahan Saldo di Variables, suara di Sound, animasi ukuran di Looks, dan jeda di Control.

Cari berdasarkan fungsi

Scratch membagi blok ke dalam kategori berdasarkan fungsinya. Karena ingin merespons klik, cari blok event di kategori kuning Events. Karena ingin mengubah angka, buka kategori oranye Variables.

Untuk animasi, gunakan blok ungu dari Looks. Untuk suara, gunakan blok Sound. Blok jeda wait ada pada kategori Control yang berwarna kuning-oranye.

Nama dan warna ini membantu kamu mencari blok. Kalau sebuah blok sulit ditemukan, coba tanyakan: “Aku sedang membuat perintah untuk apa?” Bukan hanya mengikuti warna pada gambar.

Lakukan langkah ini di Scratch

Klik sprite Bowl pada daftar sprite. Dari kategori Events, tarik blok when green flag clicked ke Code Area. Tambahkan set [Saldo] to (0) dari Variables tepat di bawahnya.

Selanjutnya gunakan go to x: (0) y: (-20) dari Motion agar Bowl kembali ke posisi yang diinginkan. Tambahkan set size to (100)% dari Looks supaya ukuran tidak berubah setelah percobaan sebelumnya. Dalam contoh modul, terdapat pesan Klik aku untuk menabung! selama dua detik; kamu boleh menambahkannya setelah blok dasar bekerja.

Klik bendera hijau untuk menguji. Angka Saldo harus 0 dan Bowl berada pada posisi awal. Jika belum, cek apakah Blocks dipasang pada sprite yang benar.

Berhenti sebentar untuk mengetes

Checkpoint adalah pemeriksaan kecil sebelum menambah fitur lain. Lebih mudah memperbaiki satu script sederhana daripada menunggu semua kode selesai.

Jika Saldo tetap 50 setelah Green Flag, periksa apakah kamu memasang set Saldo to 0. Blok change Saldo by 0 bukan cara mereset, karena menambahkan nol tidak mengubah nilainya.

Jika ukuran Bowl masih terlalu besar, pastikan set size to 100% ada di script Green Flag. Jangan berpindah ke fitur klik sebelum semua hasil awal ini benar.

Event klik adalah pemicu

Tetap pilih sprite Bowl. Dari Events, tarik blok when this sprite clicked ke Code Area. Blok ini tidak dipasang di bawah Green Flag, tetapi menjadi script sendiri karena pemicunya berbeda.

Di bawah event klik, pasang change Saldo by 10. Artinya setiap pemain mengklik Bowl, Scratch mengambil Saldo lama dan menambahkannya 10. Ketika kamu klik satu kali dari 0, hasilnya 10. Klik kedua menjadi 20.

Modul juga menambahkan suara Coin, ukuran menjadi 115%, jeda 0,05 detik, lalu ukuran kembali 100%. Utamakan perubahan Saldo terlebih dahulu, kemudian tambahkan efek satu per satu.

Kenapa set bukan untuk menabung?

Saat membuat game, sering ada blok yang tampaknya benar tetapi menghasilkan angka yang salah. Contohnya set Saldo to 10 di bawah event klik. Blok itu akan mengisi Saldo menjadi 10 setiap kali klik. Jadi, berapa kali pun pemain menekan Bowl, nilainya tetap 10.

Untuk membuat nilai terus bertambah, pilih change Saldo by 10. Jika Saldo sekarang 40, Scratch menghitung 40 + 10 = 50.

Kamu dapat menguji kode tanpa perlu menghafal. Klik bendera hijau, tekan Bowl beberapa kali, lalu amati angka yang muncul. Bandingkan angka yang diharapkan dengan angka sebenarnya.

Reward itu umpan balik, bukan nilai uang

Efek suara dan animasi membuat pemain tahu bahwa kliknya diterima. Kita menyebutnya feedback atau respons dari game. Pada proyek contoh, Bowl membesar menjadi 115%, menunggu 0,05 detik, lalu kembali ke 100%.

Urutan ini penting. Jika kamu hanya memasang set size to 115% tanpa mengembalikannya, Bowl bisa terus tampak terlalu besar.

Pada starter, suara yang tersedia pada Bowl bernama Pop, sedangkan contoh final memakai Coin. Jika ingin sama seperti modul, buka tab Sounds pada Bowl dan tambahkan suara Coin; pilih suara yang benar di blok Sound. Kamu boleh memakai suara yang sudah tersedia selama tujuan respons klik terpenuhi.

Buktikan perubahan nilai

Klik gambar Bowl sebanyak lima kali tanpa mereset. Angka Saldo seharusnya berturut-turut 10, 20, 30, 40, dan 50. Setelah itu, tekan Reset untuk kembali ke 0.

Latihan ini membantu kamu memahami hasil yang harus terlihat saat project Scratch diuji. Di Scratch aslinya, jangan hanya mengeklik slide ini; kamu tetap perlu membuat Blocks pada sprite Bowl.

Saat menguji, beri perhatian pada urutan angka. Jika ada klik yang tidak menambah nilai 10, cek apakah kamu menekan sprite yang benar dan apakah script sudah terhubung.

Dua sprite berarti dua pemicu berbeda

Sprite Koin adalah tambahan visual. Dalam proyek contoh, klik pada sprite Koin membuatnya berpindah dari atas menuju Bowl, kemudian menghilang. Script Koin tidak mengubah variabel Saldo.

Perhatikan perbedaannya: event pada Bowl menaikkan Saldo, sedangkan event pada Koin menggerakkan gambar koin. Karena pemicunya berbeda, klik Bowl tidak otomatis menjalankan animasi koin pada kode contoh.

Fitur Koin tidak perlu dikerjakan dahulu jika script Saldo belum benar. Jika waktu masih ada, kamu bisa menambahkan animasinya sebagai sentuhan akhir atau tantangan pengayaan.

Mencari bug dengan hasil yang terlihat

Bug adalah masalah pada program yang membuat hasilnya tidak sesuai harapan. Untuk menemukan bug, jangan menebak semua blok sekaligus. Periksa hasil yang salah dan cari blok yang bertanggung jawab.

Jika Saldo berhenti di 10, kemungkinan kamu memakai set Saldo to 10 ketika klik. Ganti dengan change Saldo by 10. Jika Saldo tidak kembali ke 0 ketika mulai ulang, pastikan set Saldo to 0 ada di script Green Flag.

Jika ukuran Bowl tidak kembali normal, periksa urutan set size to 115%, wait 0.05 seconds, dan set size to 100%. Setelah memperbaiki satu bug, jalankan ulang pengujian.

Pakai jejak angka saat testing

Tabel ini disebut trace: catatan perubahan nilai langkah demi langkah. Trace membantu kita memeriksa apakah urutan di program sesuai dengan yang diharapkan.

Saat pertama dimulai, Saldo bernilai 0. Setiap klik menambah 10 dari angka sebelumnya, bukan mengganti angka langsung menjadi 10. Setelah lima kali klik, Saldo bernilai 50. Menekan bendera hijau lagi mengulang permainan dari 0.

Ketika mencoba sendiri, kamu boleh membuat trace di kertas. Cukup tuliskan aksi yang dilakukan, angka yang seharusnya muncul, dan angka yang benar-benar ditampilkan Scratch.

Expected dan actual harus cocok

Expected adalah hasil yang seharusnya terlihat, sementara actual adalah hasil yang benar-benar muncul di Scratch. Saat testing, bandingkan keduanya.

Jangan hanya mencoba satu klik. Uji beberapa klik, lalu uji reset. Dengan cara ini kamu dapat menemukan bug yang tidak terlihat saat percobaan pertama. Misalnya game tampak benar pada klik pertama tetapi ternyata tidak menambah Saldo pada klik kedua.

Kalau ada uji yang gagal, periksa script yang berkaitan, perbaiki satu bagian, lalu ulangi uji. Kamu tidak perlu menambahkan fitur baru sebelum bagian wajib berhasil.

Jika kamu membuat screenshot untuk tugas, tampilkan saja angka simulasi. Tidak perlu menulis nama lengkap, nomor rekening, atau kata sandi.

Yang dikumpulkan adalah project, bukan hanya gambar

File .sb3 adalah berkas proyek Scratch yang berisi sprite, backdrop, suara, dan Blocks. Guru dapat membuka file itu untuk memeriksa kode dan menjalankan game. Screenshot Stage saja tidak memperlihatkan semua Blocks.

Jika menggunakan Scratch Desktop, pilih File → Save to your computer. Jika menggunakan Scratch di browser, pastikan kamu mengunduh file proyek sesuai menu yang tersedia. Cek nama file agar tidak tertukar dengan starter atau proyek guru.

Buka LMS sesuai akun sekolah. Pilih tugas Sesi 25, unggah berkas yang benar, kemudian tekan tombol Submit/Kirim. Setelah itu cek status pengumpulan pada LMS.

Periksa hasil dengan mandiri

Checklist ini membantu kamu menilai pekerjaan sendiri. Kamu tidak harus memiliki desain yang persis sama dengan teman, tetapi fungsi utamanya harus sesuai tujuan pembelajaran.

File yang akan dikumpulkan harus menyimpan hasil codingmu, bukan hanya starter yang belum ditambah Blocks. Beri waktu untuk mengecek nama file sebelum mengunggahnya.
