Dari “bisa bergerak” menjadi “punya aturan”

Sesi 21 membuat fondasi game: layout, START, FINISH, reset, dan movement 4 arah.

Hari ini kita menambahkan aturan agar game punya tantangan dan tujuan yang jelas.

Semua code movement dari Sesi 21 tetap dipakai. Kita tidak membuat project baru dari nol.

Kita melanjutkan file yang sama

Sebelum menambah code, coba Green Flag dan empat tombol arah. Pastikan fondasi masih bekerja.

Buat salinan versi Sesi 22 jika diarahkan guru. Ini membantu menjaga versi Sesi 21 sebagai cadangan.

Aturan game adalah keputusan

Game perlu mengecek keadaan, lalu melakukan respons yang sesuai.

Dalam Scratch, pola ini sering dibuat dengan if. Bagian kondisi berisi pertanyaan, misalnya “apakah menyentuh warna merah?”. Bagian aksi berisi apa yang harus dilakukan jika jawabannya benar.

IF tidak selalu menjalankan aksinya

IF lebih mirip penjaga yang bertanya: “Apakah kondisi ini terjadi?”

Kalau jawabannya benar, aksi di dalamnya dijalankan. Kalau salah, Scratch melewatinya dan lanjut ke bagian berikutnya.

Pilih Sensing sesuai objeknya

Dinding adalah bagian dari gambar backdrop, jadi kita mengeceknya dengan touching color?.

FINISH dibuat sebagai sprite celengan, jadi kita mengeceknya dengan touching [celengan]?.

Kalau metode sensing salah, aturan game tidak akan merespons objek yang kita maksud.

Pengecekan harus berlangsung terus

Kalau IF hanya dijalankan sekali saat Green Flag, sentuhan yang terjadi beberapa detik kemudian bisa tidak terdeteksi.

Dengan forever, Scratch mengulang pengecekan berkali-kali selama game berjalan. Itulah sebabnya aturan collision dan FINISH diletakkan di dalam loop ini.

Tulis expected result

Sebelum coding, tentukan hasil yang seharusnya terjadi. Ini membuat testing lebih mudah.

Nanti kamu tinggal membandingkan: “Expected: kembali START. Actual: apa yang benar-benar terjadi?”

Kalau berbeda, berarti ada bagian yang perlu di-debug.

Baca code collision

forever membuat pengecekan terus dilakukan.

if touching color merah? mengecek apakah pemain menyentuh warna dinding.

Jika benar, go to x: -170 y: -130 mengembalikan pemain ke START pada contoh project.

Jangan membuat dua START

Koordinat awal dan koordinat reset harus konsisten.

Kalau kamu memakai layout berbeda dari contoh, tidak masalah. Gunakan koordinat START milik project-mu sendiri, lalu pakai angka yang sama pada aturan collision.

Collision bergantung pada desain juga

Code yang benar tetap bisa terasa aneh jika warna dinding tidak persis sama atau jalurnya terlalu sempit.

Karena itu debugging game tidak hanya melihat block. Kita juga mengecek ukuran sprite, ketebalan dinding, dan nilai movement.

Deteksi tujuan dengan sprite

Ketika robot menyentuh celengan, kondisi FINISH menjadi benar.

Tapi menyentuh saja belum cukup. Kita masih perlu memberi tahu bagian lain dari project bahwa pemain sudah menang. Untuk itulah kita memakai broadcast.

Dua IF, dua aturan

Di dalam satu loop forever, pemain dapat mengecek dua kondisi berbeda.

IF pertama menangani dinding. IF kedua menangani FINISH.

Ketika touching [celengan]? benar, pemain menjalankan broadcast [menang].

Broadcast menghubungkan bagian project

Sprite dan Stage adalah bagian yang berbeda. Broadcast membantu mereka berkomunikasi tanpa harus berada di script yang sama.

Nama pesan harus cocok. Jika pemain mengirim menang, penerima juga harus menunggu pesan menang.

Stage menerima pesan

Block when I receive [menang] adalah event. Script ini menunggu sampai pesan dikirim.

Setelah pesan diterima, Stage mengganti backdrop menjadi halaman_menang.

Dengan begitu, kemenangan tidak dikendalikan langsung oleh tombol keyboard, tetapi oleh kondisi FINISH.

Ending memberi tanda tujuan tercapai

Backdrop kemenangan membuat pemain tahu bahwa game sudah selesai.

Kamu boleh menambahkan pesan singkat seperti “Game selesai!” atau “Target tabungan tercapai!”. Hindari teks terlalu panjang agar mudah dibaca.

Stage tidak memiliki balon dialog seperti sprite, jadi pesan visual lebih cocok diletakkan pada backdrop atau melalui sprite narator.

Ending bukan akhir dari program

Setelah menang, pemain harus bisa menekan Green Flag dan memulai ulang.

Karena itu script Green Flag tetap penting: backdrop kembali ke game, sprite terlihat, dan posisi kembali ke START.

Testing restart adalah bagian wajib. Jangan hanya menguji sampai halaman menang muncul.

Dua jenis event yang berbeda

Green Flag menyiapkan kondisi awal. Event when I receive menang menyiapkan kondisi akhir.

Pikirkan game sebagai dua keadaan: siap bermain dan menang. Code membantu berpindah antara kedua keadaan itu dengan jelas.

Trace pesan satu langkah demi satu

Kalau halaman menang tidak muncul, jangan langsung mengubah semuanya.

Cek urutan: apakah touching celengan benar? Apakah broadcast dikirim? Apakah Stage menunggu nama pesan yang sama? Apakah backdrop tujuan sudah ada?

Dengan menelusuri alur, kita bisa menemukan titik yang berhenti.

Collision perlu diuji dari banyak arah

Sprite bisa menyentuh dinding dengan cara yang berbeda. Karena itu test hanya dari satu arah belum memberi bukti yang cukup.

Kalau ada arah tertentu yang bisa menembus, cek ketebalan dinding dan nilai movement.

Expected result harus jelas

Expected result untuk FINISH bukan sekadar “robot sampai tujuan”.

Game dianggap berhasil jika touching FINISH memicu broadcast dan Stage benar-benar berubah ke halaman kemenangan.

Kalau robot menyentuh celengan tetapi backdrop tetap sama, telusuri alur broadcast.

Game harus kembali ke kondisi awal

Restart yang baik mengembalikan backdrop game, menampilkan pemain, dan mengembalikan posisi START.

Kalau satu bagian tertinggal—misalnya backdrop masih halaman menang—berarti reset belum lengkap.

Fitur baru tidak boleh merusak fitur lama

Setelah menambahkan collision dan ending, cek kembali movement 4 arah.

Ini disebut regression check: memastikan bagian yang sebelumnya sudah bekerja tetap aman setelah code baru ditambahkan.

Debug dari gejala

Setiap gejala memberi petunjuk tentang bagian code yang perlu dicek.

Kalau FINISH tidak terdeteksi, jangan mengubah collision dinding. Fokus pada touching sprite dan broadcast.

Kalau backdrop tidak berubah, cek nama pesan dan script Stage.

Hubungkan game dengan pesan baik

Celengan dan target dapat digunakan untuk mengingatkan bahwa tujuan finansial biasanya dicapai bertahap.

Pesan tidak perlu menghakimi. Fokus pada kebiasaan positif seperti membuat target, menabung bertahap, dan memikirkan prioritas.

Challenge tidak boleh menggantikan testing fitur wajib.

Jangan menyimpan sebelum testing

Versi Sesi 22 sebaiknya sudah melewati test rintangan, FINISH, restart, dan regression movement.

Simpan file yang benar-benar kamu uji. Ini akan menjadi dasar untuk sesi testing dan penyempurnaan berikutnya.

Jelaskan dengan alur, bukan hafalan

Kalau kamu bisa menjelaskan “kondisi → aksi → hasil”, berarti kamu sudah memahami aturan game.

Contoh: touching color merah → go to START → pemain mendapat konsekuensi karena menyentuh rintangan.

Ingat hubungan antar-block

Sebelum quiz, bedakan fungsi IF, Sensing, forever, broadcast, when I receive, dan Green Flag reset.

Pikirkan perannya dalam alur game, bukan hanya warna block-nya.
