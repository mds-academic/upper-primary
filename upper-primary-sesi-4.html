Project yang Akan Dibuat

Di sesi ini, kamu akan membuat Piano Digital di Scratch. Project ini membuat keyboard komputer terasa seperti alat musik sederhana. Saat tombol tertentu ditekan, Scratch akan memainkan suara piano yang sesuai.

Tombol yang dipakai adalah A, S, D, dan F. Keempat tombol ini berada berdekatan di keyboard, jadi lebih mudah dimainkan dengan tangan kiri. Setiap tombol akan dipasangkan dengan satu nada: A untuk Do, S untuk Re, D untuk Mi, dan F untuk Fa.

Target minimum

Minimal dua tombol menghasilkan dua suara yang berbeda. Target lengkapnya adalah empat tombol A, S, D, dan F dapat menghasilkan empat nada berbeda.

Contoh hasil

Ketika kamu menekan tombol A, terdengar nada Do. Ketika kamu menekan tombol S, terdengar nada Re. Jika tombolnya berbeda, suaranya juga harus berbeda.

Project ini melatih kamu memahami event, yaitu kejadian yang membuat kode berjalan. Kali ini, event-nya bukan hanya Green Flag, tetapi tombol keyboard yang ditekan.

Misi Belajar Sesi 4

Hari ini kamu belajar bagaimana sebuah project bisa merespons tombol keyboard. Kalau pada sesi sebelumnya kamu lebih sering memakai Green Flag untuk memulai program, di sesi ini kamu akan memakai tombol keyboard sebagai pemicu.

Yang akan dipelajari

  • Event: kejadian yang membuat kode berjalan.
  • Keyboard event: kode berjalan saat tombol keyboard tertentu ditekan.
  • Key mapping: memasangkan tombol dengan aksi tertentu.
  • Testing: mencoba tombol satu per satu untuk memastikan hasilnya benar.

Sesi ini juga mengajak kamu memakai perangkat dengan bertanggung jawab. Karena project memakai suara, kamu perlu memperhatikan volume agar tidak mengganggu teman lain.

Fokus utamanya bukan memainkan lagu yang sulit. Fokusnya adalah membuat setiap tombol bekerja sesuai pasangan nada yang sudah direncanakan.

Persiapan Perangkat

Sebelum membuat Piano Digital, pastikan perangkatmu siap. Project ini membutuhkan keyboard yang bisa ditekan dengan nyaman dan suara yang bisa terdengar saat testing.

Yang perlu dicek

  • Keyboard dapat digunakan.
  • Speaker atau headphone siap dipakai.
  • Volume tidak terlalu keras dan tidak terlalu kecil.
  • Scratch sudah terbuka dan project siap dibuat.
  • Tangan bersih dan kering sebelum menggunakan keyboard.

Kalau memakai headphone, mulai dari volume rendah terlebih dahulu. Setelah itu, naikkan sedikit jika suara belum terdengar. Hindari langsung memakai volume tinggi.

Ingat

Keyboard adalah alat belajar. Tekan tombol dengan lembut. Menekan tombol terlalu keras tidak membuat suara menjadi lebih bagus.

Event sebagai Pemicu Kode

Event adalah kejadian yang membuat Scratch menjalankan rangkaian blok. Tanpa event, blok yang sudah disusun tidak akan berjalan sendiri.

Contoh event yang sudah sering dipakai adalah when green flag clicked. Saat Green Flag diklik, Scratch menjalankan blok yang tersambung di bawahnya.

Contoh event di kehidupan sehari-hari

Bel sekolah berbunyi → siswa mulai masuk kelas. Tombol lampu ditekan → lampu menyala. Keyboard ditekan → Piano Digital memainkan suara.

Di Piano Digital, tombol keyboard menjadi pemicu. Saat tombol A ditekan, Scratch menjalankan script tombol A. Saat tombol S ditekan, Scratch menjalankan script tombol S.

Green Flag dan Keyboard Event

Green Flag dan keyboard event sama-sama bisa memulai kode, tetapi penggunaannya berbeda. Green Flag cocok untuk memulai project dari awal. Keyboard event cocok untuk project yang perlu merespons tombol tertentu.

Perbedaannya

  • Green Flag: menjalankan project saat tombol bendera hijau diklik.
  • Keyboard event: menjalankan script saat tombol keyboard tertentu ditekan.

Piano Digital lebih cocok memakai keyboard event karena piano dimainkan dengan menekan tombol. Kalau hanya memakai Green Flag, suara akan keluar saat project dimulai saja, bukan saat kamu ingin memainkan nada.

Kesalahan yang sering terjadi

Semua suara dipasang di bawah Green Flag. Akibatnya, suara bisa keluar sekaligus saat project dimulai, bukan saat tombol A, S, D, atau F ditekan.

Key Mapping

Key mapping berarti memasangkan tombol dengan aksi. Pada Piano Digital, tombol keyboard dipasangkan dengan suara piano.

Mapping project hari ini

  • A → nada Do
  • S → nada Re
  • D → nada Mi
  • F → nada Fa

Mapping harus konsisten. Kalau tombol D direncanakan untuk nada Mi, script tombol D juga harus memakai suara Mi. Kalau salah memilih sound, pengguna akan mendengar nada yang keliru.

Key mapping tidak hanya ada di project piano. Banyak game juga memakai mapping, misalnya tombol panah untuk bergerak atau tombol spasi untuk melompat.

Etika Menggunakan Keyboard

Project musik biasanya membuat kelas menjadi lebih ramai. Supaya semua tetap nyaman, kita perlu memakai keyboard dan suara dengan baik.

Yang dilakukan

  • Tekan tombol dengan lembut.
  • Gunakan volume yang aman.
  • Jaga tangan tetap bersih dan kering.
  • Dengarkan instruksi saat testing dilakukan bergantian.

Yang dihindari

  • Menekan tombol terlalu keras.
  • Memainkan suara keras terus-menerus.
  • Makan atau minum dekat laptop.
  • Mengganggu teman yang sedang testing.

Menjaga perangkat adalah bagian dari menjadi digital creator yang bertanggung jawab.

Aman atau Tidak?

Aktivitas ini melatih kamu membedakan kebiasaan yang aman dan tidak aman saat memakai perangkat. Jawaban yang benar bukan hanya tentang project selesai, tetapi juga tentang cara belajar yang bertanggung jawab.

Saat mengerjakan Piano Digital, kamu mungkin ingin menekan tombol berkali-kali. Itu boleh saat testing, tetapi tetap harus lembut dan tidak terlalu keras.

Contoh aman

Menekan tombol A satu kali, mendengar hasilnya, lalu lanjut tombol S. Ini lebih baik daripada menekan semua tombol cepat-cepat tanpa mengecek hasilnya.

Kalau kamu ragu apakah tindakanmu aman, tanyakan: apakah ini menjaga perangkat? apakah ini mengganggu teman? apakah ini membantu testing?

Tebak Tombol

Sebelum membuat script, pastikan kamu memahami pasangan tombol dan nada. Ini akan mengurangi kesalahan saat memilih event di Scratch.

Misalnya, jika pertanyaannya adalah “tombol mana untuk nada Re?”, kamu perlu mengingat mapping: A = Do, S = Re, D = Mi, F = Fa. Jadi, jawabannya adalah S.

Gunakan cara cepat

Bayangkan urutan nada dari kiri ke kanan di keyboard: A-S-D-F. Urutannya sama seperti Do-Re-Mi-Fa.

Latihan kecil seperti ini membantu kamu lebih siap saat masuk ke bagian coding.

Kebutuhan Project

Project Piano Digital membutuhkan beberapa bagian dasar. Bagian yang paling penting adalah sprite dan suara. Sprite menjadi objek yang ada di project, sedangkan suara menjadi output utama yang terdengar saat tombol ditekan.

Yang perlu disiapkan

  • Minimal satu sprite. Boleh sprite piano, robot, cat, atau karakter lain.
  • Empat suara piano atau suara nada yang berbeda.
  • Keyboard komputer untuk testing.
  • Speaker atau headphone dengan volume aman.

Jika kamu ingin menambahkan efek visual, pilih sprite yang punya minimal dua costume. Namun, efek visual hanya tambahan. Suara dari tombol tetap menjadi target utama.

Cek sebelum lanjut

Jangan sampai tombol S masih memakai suara Do. Kalau begitu, A dan S akan terdengar sama.

Checkpoint A dan S

Checkpoint dilakukan agar kamu tidak menumpuk terlalu banyak script sebelum tahu apakah bagian awal sudah benar. Uji tombol A dan S terlebih dahulu.

Yang dicek

  • Klik area Stage terlebih dahulu.
  • Tekan tombol A. Apakah nada Do terdengar?
  • Tekan tombol S. Apakah nada Re terdengar?
  • Apakah kedua suara berbeda?

Kalau A dan S belum bekerja, perbaiki dulu sebelum menambah D dan F. Testing bertahap membuat error lebih mudah ditemukan.

Kenapa bertahap?

Kalau kamu langsung membuat empat tombol dan semuanya gagal, kamu akan lebih sulit tahu bagian mana yang salah.

Efek Visual Tambahan

Setelah suara utama berhasil, kamu boleh menambahkan efek visual agar project lebih menarik. Misalnya, sprite berganti costume, berubah warna, atau menampilkan dialog singkat.

Rangkaian Lengkap

Project lengkap berisi beberapa script yang terpisah. Setiap script dimulai dengan keyboard event yang berbeda.

Struktur lengkap

  • when A key pressed → start sound Do
  • when S key pressed → start sound Re
  • when D key pressed → start sound Mi
  • when F key pressed → start sound Fa

Struktur seperti ini membuat project mudah diperiksa. Kalau nada Mi salah, kamu cukup mencari script tombol D. Kalau nada Fa tidak keluar, kamu cek script tombol F.

Biasakan menyusun script dengan rapi dan memberi jarak yang cukup agar mudah dibaca.

Testing Semua Tombol

Testing dilakukan setelah semua script dibuat. Tujuannya untuk memastikan setiap tombol menghasilkan suara yang tepat.

Langkah testing

  1. Klik area Stage terlebih dahulu.
  2. Tekan A, dengarkan suaranya.
  3. Tekan S, dengarkan suaranya.
  4. Tekan D, dengarkan suaranya.
  5. Tekan F, dengarkan suaranya.
  6. Bandingkan hasilnya dengan mapping.

Jangan menekan tombol terlalu cepat saat testing pertama. Dengarkan satu per satu agar kamu bisa tahu tombol mana yang sudah benar dan mana yang perlu diperbaiki.

Jika tombol tidak merespons

Biasanya area Stage belum aktif. Klik Stage sekali, lalu coba tekan tombol lagi.

Debugging Piano

Debugging berarti mencari penyebab project belum berjalan sesuai rencana. Pada Piano Digital, masalah yang sering muncul biasanya berhubungan dengan suara, event huruf, atau area Stage.

Urutan cek sederhana

  1. Cek volume perangkat.
  2. Cek apakah suara sudah ditambahkan di tab Sounds.
  3. Cek apakah huruf event sudah benar: A, S, D, atau F.
  4. Cek apakah setiap script memakai suara yang berbeda.
  5. Klik Stage, lalu test ulang.

Jangan langsung menghapus semua script. Pilih satu tombol yang bermasalah, lalu periksa script tombol itu saja.

Contoh

Jika tombol D mengeluarkan nada Fa, berarti event D sudah berjalan, tetapi pilihan sound-nya salah. Kamu cukup mengganti sound pada script D.
