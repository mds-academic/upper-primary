Apa tujuan sesi terakhir sprint ini?

Sesi 24 adalah puncak dari proses yang sudah kamu jalani: build → test → fix → present. Project yang kamu presentasikan adalah versi yang sudah diuji dan dirapikan pada Sesi 23.

Di sesi ini, kamu tidak perlu menambah banyak hal baru. Fokusnya adalah menyiapkan project final, menjelaskannya dengan runtut, dan mendemokan bagian paling penting dari game-mu.

Mengapa perlu persiapan ini?

Presentasi yang baik bukan hanya soal berbicara, tetapi juga soal kesiapan file. Karena itu, sebelum tampil, pastikan project bisa dibuka, pitch deck sesuai dengan project final, dan ada cadangan jika terjadi masalah teknis.

Versi file yang disarankan: Nama Panggilan - Judul Project - FINAL.

Jelaskan singkat, jelas, dan runtut

Kamu tidak perlu bercerita terlalu panjang. Yang penting, orang lain bisa mengerti project-mu: namanya apa, masalah apa yang diangkat, bagaimana solusi di dalam game, bagaimana cara memainkannya, dan bagian code mana yang paling berpengaruh.

Bagian yang paling dibanggakan bisa berupa layout labirin, sistem rintangan, halaman menang, atau cara kamu memperbaiki bug tertentu.

Kenapa urutan ini bagus?

Urutan demo membantu penonton memahami project secara bertahap. Mereka melihat game dimulai, cara menggerakkan pemain, aturan rintangan, lalu hasil akhirnya.

Kamu tidak harus menunjukkan semua jalur. Cukup pilih satu alur demo yang paling jelas dan memperlihatkan fitur utama project.

Bagaimana memilih block penting?

Pilih block yang benar-benar membuat game bisa berjalan. Misalnya: block Green Flag untuk reset, block rintangan untuk mengembalikan pemain ke START, atau block kemenangan yang memunculkan ending.

Nanti, saat menjelaskan, ceritakan fungsi block tersebut dan apa yang terjadi jika block itu dihapus atau diubah.

Cara menjelaskannya

Kamu bisa berkata: “Block ini penting karena mengatur kondisi awal game. Saat Green Flag diklik, pemain kembali ke START dan backdrop juga kembali ke labirin. Jadi pemain bisa memulai permainan dengan rapi.”

Jika block ini dihapus, posisi pemain atau backdrop bisa salah saat game dimulai lagi.

Mengapa block ini penting?

Tanpa block ini, pemain bisa menembus dinding dan aturan game hilang. Saat menjelaskan di depan kelas, kamu bisa menyebutkan bahwa block ini adalah aturan utama yang membuat pemain harus hati-hati saat berjalan di labirin.

Dua block yang saling bekerja sama

Block pertama memeriksa apakah pemain sudah menyentuh FINISH. Jika iya, block itu mengirim pesan menang. Lalu, block kedua menerima pesan itu dan mengganti backdrop menjadi halaman kemenangan.

Ini contoh bagus tentang bagaimana broadcast membantu bagian-bagian project saling terhubung.

Tidak apa-apa jika belum tahu semua jawaban

Saat sesi tanya jawab, jawab berdasarkan project yang benar-benar kamu buat. Jika kamu belum tahu jawabannya, kamu boleh bilang, “Aku belum tahu pasti, tapi aku ingin mencoba cek lagi nanti.”

Kejujuran lebih penting daripada jawaban yang dibuat-buat.

Presentasi bukan harus sempurna

Dalam project digital, kadang bug tetap muncul. Yang penting adalah kamu bisa menjelaskan project dengan jujur dan tetap tenang. Ini juga menunjukkan bahwa kamu memahami project-mu sendiri.

Jika punya screenshot atau file backup, itu bisa membantu saat live demo tidak berjalan sesuai rencana.

Sikap yang perlu dijaga

Gallery Walk bukan lomba saling menjatuhkan. Ini kesempatan untuk saling belajar. Saat menjadi pengunjung, kamu boleh bertanya dan memberi ide, tetapi tetap sopan. Jangan mengejek bug dan jangan menyentuh perangkat teman tanpa izin.

Kenapa ini penting?

Kalimat-kalimat seperti ini membantu kamu memberi respons yang ramah dan bermanfaat. Project teman akan terasa dihargai, dan kamu juga belajar mengamati ide orang lain dengan lebih baik.

Jangan menunda sampai akhir

Setelah presentasi selesai, pastikan semua file atau link yang diminta benar-benar terkumpul. Ini membantu guru melihat hasil kerja finalmu dengan jelas.

Periksa kembali nama file, isi pitch deck, dan apakah screenshot yang dipilih memang sesuai dengan project final.

Yang kamu pelajari di akhir sprint

Kamu bukan hanya belajar membuat game, tetapi juga belajar menguji, memperbaiki, menjelaskan ide, dan menghargai karya teman. Ini adalah keterampilan penting saat membuat project apa pun.

Setelah sesi ini, kamu bisa melihat kembali bagaimana ide dari pitch deck berubah menjadi game yang benar-benar bisa dimainkan.
