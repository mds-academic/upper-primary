Project yang Akan Dibuat

Di Sesi 10, kamu membuat project Scratch bertema toko. Sprite berperan seperti kasir yang menyapa pembeli, bertanya barang apa yang dibeli, lalu bertanya harga barang tersebut.

Fokus belajarnya adalah cara Scratch menerima jawaban dari pengguna. Blok yang paling penting adalah ask and wait, answer, join, dan say. Jadi, meskipun judulnya “Kalkulator Harga”, versi dasar project ini belum menjumlahkan harga. Project ini membantu kamu memahami dulu cara bertanya dan memakai jawaban.

Yang akan kamu kuasai

  • Membuat sprite bertanya kepada user.
  • Memahami bahwa answer menyimpan jawaban terakhir.
  • Menggabungkan teks dan jawaban dengan join.
  • Menguji project dengan contoh barang dan harga.

Setelah pola ini kuat, kamu akan lebih siap membuat aplikasi atau game yang memakai input dari user.

Misi Belajar Hari Ini

Hari ini kamu akan belajar membuat percakapan sederhana antara sprite dan user. Percakapannya tidak hanya tampil di layar, tetapi juga menerima jawaban yang diketik user.

Alur belajarnya dimulai dari mencoba simulasi toko, lalu mengenal blok ask and wait, memahami answer, dan akhirnya menyusun rangkaian blok di Scratch.

Urutan belajar

  1. Coba dulu sebagai user: isi nama barang dan harga.
  2. Pahami blok yang membuat pertanyaan.
  3. Pahami tempat Scratch menyimpan jawaban.
  4. Gabungkan teks dan jawaban supaya balon kata enak dibaca.
  5. Test project dengan beberapa contoh.

Tujuan akhirnya bukan hanya project terlihat jalan, tetapi kamu bisa menjelaskan mengapa sprite bisa menampilkan jawaban yang kamu ketik.

Persiapan Sebelum Coding

Workspace yang rapi membuat proses coding lebih mudah. Untuk project ini, kamu hanya membutuhkan satu sprite yang berperan sebagai kasir dan satu backdrop toko.

Karena project bertema harga, gunakan angka latihan. Misalnya harga pensil Rp3.000 atau buku Rp8.000. Kita tidak membutuhkan data keuangan asli.

Tips sebelum mulai

Kalau backdrop terlalu ramai, balon kata dari sprite bisa sulit dibaca. Pilih backdrop toko yang sederhana atau atur posisi sprite agar balon katanya tidak menutupi bagian penting.

Menghubungkan Coding dengan Harga Barang

Project ini memakai tema toko supaya coding terasa dekat dengan kehidupan sehari-hari. Saat membeli barang, kita biasanya mengingat dua hal: nama barang dan harga.

Di Scratch, robot kasir akan menanyakan dua hal itu. Jawaban user akan dipakai lagi untuk membuat kalimat output. Jadi project ini melatih dua hal sekaligus: berpikir tentang harga barang dan memahami input dari user.

Catatan

Harga barang bisa berbeda di setiap toko atau daerah. Angka di kelas hanya contoh latihan, bukan daftar harga resmi.

Aktivitas Tebak Harga

Aktivitas ini membantu kamu berpikir bahwa harga barang punya kisaran yang masuk akal. Misalnya, harga pensil biasanya tidak sama dengan harga tas atau sepatu.

Kegiatan ini juga menjadi pemanasan sebelum project Scratch. Nanti robot kasir akan bertanya nama barang dan harga. Kalau kamu punya perkiraan harga, kamu bisa mengisi jawaban dengan lebih sadar.

Kenapa perlu kisaran?

Kisaran membantu kita mengecek apakah angka yang diketik terlalu kecil, terlalu besar, atau masih masuk akal untuk contoh latihan.

Mencoba Tampilan sebelum Coding

Slide kiri adalah simulator sederhana dari project yang akan kamu buat di Scratch. Tujuannya agar kamu merasakan dulu bagaimana project dipakai oleh user sebelum menyusun bloknya.

Coba isi barang dan harga, lalu tekan Green Flag. Robot akan menyapa, menampilkan barang yang kamu isi, menampilkan harga, lalu menutup percakapan dengan ucapan terima kasih.

Yang perlu diamati

  • Apa pertanyaan pertama dari robot?
  • Apa jawaban yang dipakai untuk balon kata pertama?
  • Apa pertanyaan kedua dari robot?

Setelah memahami alurnya sebagai user, kamu akan lebih mudah membuat versi Scratch menggunakan ask, answer, join, dan say.

Testing dari Sisi User

Project yang baik tidak hanya bekerja untuk satu contoh. Kalau user memasukkan “pensil”, output harus menyebut pensil. Kalau user memasukkan “roti”, output harus ikut berubah menjadi roti.

Itulah gunanya blok answer. Scratch mengambil jawaban terakhir yang diketik user, lalu kita bisa menampilkannya kembali dalam balon kata.

Contoh perilaku benar

Input barang = roti → output: “Barang yang kamu beli adalah: roti”. Input harga = 6000 → output: “Harga barangmu adalah Rp: 6000”.

Memahami ask and wait

ask and wait adalah blok dari kategori Sensing. Blok ini menampilkan pertanyaan, membuka kotak jawaban, lalu menunggu sampai user mengetik dan menekan Enter atau tombol centang.

Dalam project Toko Kiko, blok ini dipakai dua kali. Pertama untuk bertanya nama barang. Kedua untuk bertanya harga barang.

Kenapa memakai ask and wait?

Karena project membutuhkan input dari pengguna. Tanpa ask and wait, user tidak punya tempat untuk memasukkan jawaban.

Memahami answer

Blok answer menyimpan jawaban terakhir dari blok ask and wait. Kata “terakhir” penting. Jika ada dua pertanyaan, isi answer bisa berubah setelah pertanyaan kedua dijawab.

Karena itu, pada project sample, jawaban barang langsung dipakai setelah pertanyaan barang. Setelah itu, Scratch bertanya harga, dan answer berubah menjadi harga.

Contoh

  1. Ask: “Kamu beli barang apa?” → user menjawab “pensil” → answer = pensil.
  2. Ask: “Berapa harga barang yang kamu beli?” → user menjawab “3000” → answer = 3000.

Kalau suatu hari kamu ingin menyimpan jawaban lama untuk dipakai lagi nanti, kamu perlu belajar variabel. Untuk sesi ini, kita cukup memakai answer langsung setelah pertanyaan.

Fungsi join

join adalah blok dari kategori Operators. Fungsinya menggabungkan dua bagian teks menjadi satu kalimat.

Kalau kamu hanya memakai answer, balon kata mungkin hanya menampilkan “pensil”. Itu benar, tetapi kurang jelas. Dengan join, sprite bisa mengatakan “Barang yang kamu beli adalah: pensil”.

Struktur join

  • Bagian pertama: teks tetap yang kamu tulis sendiri.
  • Bagian kedua: jawaban user dari blok answer.

Join tidak mengubah jawaban. Join hanya membuat output lebih ramah dibaca.

Output Harga yang Mudah Dibaca

Harga berupa angka saja bisa membuat orang bertanya, “Ini angka apa?” Karena itu, output sebaiknya diberi keterangan.

Project sample menggunakan kalimat seperti “Harga barangmu adalah Rp: 3000”. Kalimat ini memberi konteks bahwa angka yang ditampilkan adalah harga dalam Rupiah.

Kenapa tidak pakai Rp di input?

Untuk latihan dasar, lebih mudah jika user mengetik angka polos. Scratch akan menampilkan keterangan Rp melalui teks join.

Di project yang lebih lanjut, kita bisa belajar membuat format harga yang lebih rapi. Untuk sesi ini, fokusnya adalah menerima input dan menampilkannya kembali.

Alur Input, Process, Output

Project ini bisa dibaca dengan pola Input → Process → Output. Pola ini sering dipakai untuk memahami program.

Dalam project Sesi 10

  • Input: user mengetik barang dan harga.
  • Process: Scratch menyimpan jawaban di answer dan menggabungkannya dengan teks memakai join.
  • Output: sprite menampilkan kalimat di balon kata.

Kalau ada bug, cek alur ini satu per satu. Apakah input masuk? Apakah join benar? Apakah say menampilkan kalimat yang tepat?

Kamus Blok Sesi 10

Tabel di kiri adalah kamus kecil untuk project Sesi 10. Kalau kamu lupa fungsi sebuah blok, kembali ke slide ini.

Project ini memakai beberapa kategori blok: Events, Looks, Sensing, dan Operators. Ini menunjukkan bahwa project Scratch biasanya dibangun dari beberapa jenis blok sekaligus.

Blok inti

Dua blok yang paling baru dan penting adalah ask and wait dan answer. Keduanya bekerja berpasangan: ask membuat pertanyaan, answer menyimpan jawabannya.

Langkah 1: Event dan Sapaan

Blok when green flag clicked adalah pemicu awal. Saat Green Flag diklik, Scratch menjalankan blok yang tersambung di bawahnya.

Setelah itu, sprite menyapa pembeli dengan say for seconds. Di project sample, robot mengatakan “Selamat datang di toko Kiko” selama 2 detik.

Kenapa perlu sapaan?

Sapaan membuat project terasa seperti percakapan toko, bukan hanya kumpulan pertanyaan mendadak.

Langkah 2: Bertanya Barang

Di bagian ini, sprite mulai meminta input dari user. Pertanyaannya adalah “Kamu beli barang apa?”.

Scratch akan menunggu user menjawab. Setelah user mengetik jawaban, blok answer berisi nama barang tersebut.

Contoh

Jika user mengetik “pensil”, maka setelah pertanyaan ini, answer = pensil.

Karena answer masih berisi nama barang, kita harus segera memakainya untuk membuat kalimat output barang.

Langkah 3: Menampilkan Barang

Setelah user menjawab nama barang, kita perlu menampilkan jawaban itu dengan kalimat yang jelas. Caranya memakai join di dalam blok say for seconds.

Bagian pertama join adalah teks tetap: “Barang yang kamu beli adalah: ”. Bagian kedua adalah answer. Jika answer berisi “roti”, hasil join menjadi “Barang yang kamu beli adalah: roti”.

Kesalahan yang sering terjadi

Kalau kamu menaruh teks saja tanpa answer, output tidak akan mengikuti jawaban user. Kalau kamu menaruh answer saja tanpa teks, output kurang jelas.

Langkah 4: Bertanya Harga

Pertanyaan kedua meminta harga barang. Sama seperti sebelumnya, Scratch akan menunggu user mengetik jawaban.

Setelah user menjawab harga, isi answer berubah. Jika sebelumnya answer berisi “pensil”, setelah pertanyaan harga dijawab, answer bisa menjadi “3000”.

Kenapa ini penting?

Karena answer hanya menyimpan jawaban terakhir. Jadi urutan penggunaan answer harus tepat.

Langkah 5: Menampilkan Harga

Bagian ini mirip dengan output barang, tetapi teks awalnya berbeda. Sekarang kita ingin menjelaskan bahwa jawaban user adalah harga.

Gunakan join dengan teks “Harga barangmu adalah Rp: ”, lalu gabungkan dengan answer. Karena pertanyaan terakhir adalah pertanyaan harga, answer sekarang berisi harga.

Contoh

User menjawab 5000 → sprite mengatakan “Harga barangmu adalah Rp: 5000”.

Kalau output justru menampilkan nama barang di bagian harga, cek apakah urutan pertanyaan dan join sudah sesuai.

Langkah 6: Penutup Percakapan

Setelah barang dan harga ditampilkan, sprite bisa menutup percakapan dengan ucapan terima kasih. Ini membuat project terasa lebih natural.

Blok yang dipakai tetap say for seconds. Bedanya, kali ini tidak perlu join karena kalimatnya tidak membutuhkan jawaban user.

Contoh output

“terimakasih sudah berbelanja di toko Kiko”

Kamu boleh merapikan huruf besar/kecil jika ingin, misalnya “Terima kasih sudah berbelanja di Toko Kiko.” Yang penting pesan penutupnya jelas.

Membaca Rangkaian Lengkap

Slide ini merangkum semua langkah project. Pseudocode membantu kamu membaca logika sebelum melihat screenshot blok Scratch yang lengkap.

Baca dari atas ke bawah. Pertama sprite menyapa. Kedua sprite bertanya barang. Ketiga sprite menampilkan jawaban barang. Keempat sprite bertanya harga. Kelima sprite menampilkan harga. Terakhir sprite mengucapkan terima kasih.

Hal yang perlu dicek

Pastikan setiap blok answer dipakai setelah pertanyaan yang tepat. Answer setelah pertanyaan barang berbeda dari answer setelah pertanyaan harga.

Membaca Blocks tanpa Menjalankan

Reading Blocks berarti memprediksi apa yang akan dilakukan program sebelum menekan Green Flag. Ini membantu kamu menemukan bug lebih cepat.

Jika jawaban pertama adalah “buku tulis”, output barang harus menyebut buku tulis. Jika jawaban kedua adalah “10000”, output harga harus menyebut 10000.

Kunci prediksi

Answer selalu mengikuti pertanyaan terakhir. Jadi lihat dulu pertanyaan mana yang baru saja dijawab.

Menggunakan Trace Table

Trace table membantu kamu melacak data dari input sampai output. Setiap baris menunjukkan satu percobaan.

Dengan trace table, kamu bisa memastikan bahwa barang dan harga tidak tertukar. Jika output barang malah menampilkan harga, berarti ada blok answer atau join yang perlu dicek.

Cara membaca

Lihat kolom input dulu, lalu cocokkan dengan output. Output harus mengikuti jawaban pada percobaan yang sama.

Testing dengan Beberapa Contoh

Testing berarti mengecek apakah project bekerja sesuai rencana. Jangan hanya mengetes satu barang, karena kita perlu tahu apakah output benar-benar mengikuti jawaban user.

Gunakan contoh yang sederhana. Saat testing awal, tulis harga tanpa titik, koma, atau simbol Rp agar tidak membingungkan.

Jika hasil tidak sesuai

Jangan langsung hapus semua blok. Cek bagian yang paling dekat dengan masalah: pertanyaan, answer, join, atau say.

Debugging Terarah

Bug adalah hal biasa saat coding. Yang penting adalah cara mencarinya. Mulailah dari gejala yang terlihat.

Jika jawaban tidak muncul, kemungkinan masalahnya ada pada blok answer atau join. Jika pertanyaan tidak muncul, cek blok ask and wait dan sambungan dari Green Flag. Jika barang dan harga tertukar, cek urutan pertanyaan.

Aturan debugging

Ubah satu bagian saja, lalu test lagi. Kalau kamu mengubah terlalu banyak hal sekaligus, kamu akan sulit tahu bagian mana yang memperbaiki masalah.

Data Aman untuk Project Harga

Karena project membahas harga, kita perlu membedakan angka latihan dan data sensitif. Harga contoh seperti 5000 aman digunakan. Nama barang seperti pensil atau roti juga aman.

Data seperti nomor rekening, PIN, password, dan informasi pembayaran tidak boleh dipakai. Project ini tidak membutuhkan data tersebut.

Kebiasaan baik

Saat membuat project apa pun, gunakan data dummy untuk latihan. Jangan menaruh data pribadi di project atau screenshot pengumpulan.

Checklist Berhasil

Output minimum adalah batas project dianggap selesai. Tampilan yang menarik belum cukup jika alur pertanyaan dan jawaban belum benar.

Pastikan setiap bagian bekerja: Green Flag memulai, sprite menyapa, pertanyaan muncul, jawaban tersimpan, join membuat kalimat, dan output tampil di balon kata.

Sebelum challenge

Jalankan project minimal dua kali dengan barang dan harga berbeda. Jika output ikut berubah, project dasar sudah kuat.

Challenge Tambahan

Challenge hanya dikerjakan setelah project dasar berjalan. Jangan menambah fitur baru jika alur ask, answer, join, dan say belum benar.

Challenge yang aman untuk sesi ini misalnya menambah sprite barang, mengganti backdrop toko, memberi suara kasir, atau membuat sapaan lebih menarik.

Tantangan diskon

Diskon membutuhkan logika tambahan dan perhitungan. Jika belum diarahkan guru, cukup jadikan ide untuk sesi lanjutan.

Refleksi Akhir

Refleksi membantu kamu memastikan bahwa project ini benar-benar dipahami, bukan sekadar berhasil dibuat.

Kalau kamu bisa menjelaskan fungsi ask and wait, answer, dan join dengan kata-katamu sendiri, berarti kamu sudah memahami inti sesi ini.

Kalimat bantu

Ask membuat pertanyaan. Answer menyimpan jawaban terakhir. Join menggabungkan teks dan jawaban supaya output mudah dibaca.

Yang Sudah Dipelajari

Di Sesi 10, kamu belajar membuat project Scratch yang menerima input dari user. Sprite bertanya, user menjawab, Scratch menyimpan jawaban di answer, lalu project menampilkan kembali jawaban itu dengan kalimat yang rapi.

Konsep utama

  • ask and wait membuat pertanyaan dan menunggu jawaban.
  • answer menyimpan jawaban terakhir.
  • join menggabungkan teks dan jawaban.
  • say for seconds menampilkan output di balon kata.
  • Testing perlu memakai beberapa contoh barang dan harga.

Pola ini akan sangat berguna untuk project Scratch berikutnya yang membutuhkan input dari pemain atau user.
