Selamat datang di Sesi 19

Sesi ini melanjutkan konsep dari Pabrik Roti. Jika sebelumnya sprite turun dan reset, sekarang Koin juga turun dan reset, tetapi ada tambahan: pemain dapat menggerakkan Mangkuk menggunakan keyboard.

Project ini memperkenalkan game mechanic, yaitu aturan yang membuat game bisa dimainkan: Koin jatuh, Mangkuk bergerak, Koin terdeteksi saat tertangkap, lalu Koin muncul kembali.

Target Belajar

Di akhir sesi, siswa bisa menjelaskan aturan game dasar dan menyusun code untuk dua sprite: Bowl/Mangkuk dan coin/Koin.

Konsep utama sesi ini adalah event, condition, dan loop. Tombol keyboard adalah event, touching Bowl? adalah kondisi, dan forever membuat Koin terus bergerak selama game aktif.

Persiapan

Siswa perlu memastikan ada dua sprite penting: coin dan Bowl. Jika salah memilih sprite saat coding, hasilnya mudah tertukar.

Pastikan keyboard berfungsi karena kontrol Mangkuk memakai tombol panah. Testing juga perlu dilakukan berkali-kali, bukan hanya satu tangkapan.

Game Mechanic

Game bukan hanya kumpulan gambar bergerak. Game memiliki aturan sebab-akibat. Contohnya: jika Koin menyentuh Mangkuk, Koin dianggap tertangkap dan kembali ke atas.

Aturan seperti ini membuat game bisa dimainkan berulang. Jika Koin tidak pernah reset, game akan berhenti setelah satu kejadian.

Sprite

Project ini memakai dua sprite utama. Bowl menerima event keyboard, sedangkan coin bergerak otomatis dan mengecek kondisi sentuhan.

Banyak bug terjadi karena block ditaruh di sprite yang salah. Misalnya, when right arrow key pressed seharusnya ada pada Bowl, bukan coin.

Kontrol Keyboard

Mangkuk bergerak kiri-kanan, jadi yang diubah adalah posisi X, bukan Y. Nilai positif membuat sprite bergerak ke kanan, dan nilai negatif membuat sprite bergerak ke kiri.

Dalam sample project: tombol kanan memakai change x by 15, sedangkan tombol kiri memakai change x by -15.

Code Mangkuk

Code Green Flag mengatur posisi awal Mangkuk agar game mulai dari kondisi yang rapi. Setelah itu, dua event keyboard mengatur gerakan kanan dan kiri.

Testing untuk bagian ini cukup jelas: tekan panah kanan beberapa kali, tekan panah kiri beberapa kali, lalu tekan Green Flag untuk memastikan Mangkuk kembali ke posisi awal.

Pick Random

pick random -200 to 200 membuat nilai X berubah-ubah. Jadi Koin tidak selalu turun dari tempat yang sama.

Nilai Y tetap 170 karena Koin perlu muncul dari bagian atas Stage. Yang berubah hanya posisi X, yaitu kiri-kanan.

Gerak Jatuh Koin

Gerakan Koin mirip konsep Pabrik Roti: nilai Y dikurangi agar sprite turun. Bedanya, sekarang Koin menjadi bagian dari game.

Forever dipakai karena game harus terus berjalan. Jika Koin hanya jatuh satu kali, pemain hanya punya satu kesempatan dan game tidak berulang.

Reset Saat Terlewat

Jika Koin melewati batas bawah, game tidak boleh berhenti. Program perlu mengembalikan Koin ke atas agar pemain bisa mencoba lagi.

Kondisi yang dipakai adalah y position < -170. Jika benar, Koin dipindahkan ke atas dengan X acak.

Touching

touching Bowl? adalah kondisi sensing. Hasilnya hanya benar atau salah. Jika Koin sedang menyentuh Mangkuk, kondisi bernilai benar.

Ketika benar, sample project menjalankan hide, memindahkan Koin ke atas, lalu show. Urutan ini membuat Koin terlihat seperti muncul kembali.

Hide dan Show

Hide tidak memindahkan sprite. Go to yang memindahkan sprite. Show membuat sprite terlihat kembali setelah dipindahkan.

Siswa sering mengira hide otomatis menghapus atau memindahkan Koin. Padahal hide hanya menyembunyikan tampilan sprite.

Aturan Game

Tabel ini adalah algoritma sederhana game. Setiap kejadian memiliki respons. Jika siswa bingung saat coding, arahkan mereka kembali ke tabel ini.

Perhatikan bahwa Koin reset pada dua kondisi: saat tertangkap dan saat terlewat. Ini membuat game terus berjalan dalam dua kemungkinan.

Project Part A

Bangun kontrol pemain terlebih dahulu. Jika Mangkuk belum bisa bergerak, mechanic menangkap Koin tidak akan bisa diuji dengan benar.

Testing sederhana: tekan panah kanan dan kiri, lalu klik Green Flag untuk melihat apakah posisi awal kembali benar.

Project Part B

Bagian ini membuat Koin jatuh. Jangan langsung menambahkan touching sebelum Koin benar-benar bisa jatuh, karena debugging akan lebih sulit.

Jika Koin bergerak ke atas, cek tanda pada change y by. Jika Koin terlalu cepat, cek nilai wait.

Project Part C

Reset saat Koin terlewat memastikan game tidak berhenti jika pemain gagal menangkap Koin.

Letakkan if ini di dalam forever agar posisi Koin terus diperiksa selama game berjalan.

Project Part D

Deteksi tertangkap memakai touching Bowl?. Setelah kondisi benar, Koin di-reset ke atas agar permainan lanjut.

Pastikan target touching adalah Bowl. Jika target salah, Koin tidak akan bereaksi saat menyentuh Mangkuk.

Code Final Koin

Slide ini merangkum code Koin dari sample project. Ada dua kondisi di dalam forever: satu untuk Koin yang terlewat, satu untuk Koin yang tertangkap.

Jika salah satu kondisi berada di luar forever, kondisi itu hanya dicek sekali dan mechanic bisa gagal.

Trace Tertangkap

Tracing ini membantu siswa memahami bahwa Koin tidak berhenti saat tertangkap. Koin hanya disembunyikan sebentar, dipindahkan, lalu ditampilkan lagi.

Jika Koin hilang setelah tertangkap, cek urutan hide dan show. Jika Koin tidak pindah, cek block go to.

Trace Terlewat

Game tetap harus berjalan saat pemain gagal menangkap Koin. Karena itu ada kondisi y position < -170.

Jika kondisi ini tidak ada, Koin bisa terus turun keluar Stage dan tidak muncul lagi.

Testing

Testing Sesi 19 harus mencakup dua jalur Koin: tertangkap dan terlewat. Jika hanya menguji tertangkap, bug reset bawah bisa tidak terlihat.

Siswa juga perlu menguji keyboard. Kontrol pemain adalah bagian penting dari game mechanic, bukan hanya tambahan.

Debugging

Debugging kembali diarahkan dari gejala. Jika Mangkuk salah arah, cek perubahan X. Jika Koin tidak reset saat terlewat, cek kondisi Y. Jika Koin hilang, cek show.

Biasakan siswa tidak langsung menghapus seluruh script. Cari bagian mechanic yang gagal, perbaiki satu hal, lalu test ulang.

Extension Challenge

Challenge tetap berhubungan dengan mechanic utama. Mengubah kecepatan Koin melatih siswa memahami dampak nilai change y by dan wait.

Suara saat tertangkap boleh ditambahkan setelah mechanic utama stabil. Setelah menambah fitur, lakukan testing lagi.

Penyimpanan

Sebelum menyimpan, pastikan game sudah melewati semua checklist. Output minimum bukan hanya Koin bergerak, tetapi juga Mangkuk bisa dikontrol dan dua kondisi reset berjalan.

Jika pengumpulan dilakukan melalui LMS, siswa mengikuti instruksi guru. Pastikan versi yang disimpan adalah versi terakhir setelah testing.

Refleksi

Refleksi membantu siswa menghubungkan block dengan mechanic game. Mereka perlu bisa menjelaskan bukan hanya “block ini dipakai”, tetapi “block ini membuat apa terjadi dalam game”.

Jawaban yang baik menyebut event keyboard untuk kontrol, touching untuk cek sentuhan, dan reset agar game bisa terus berjalan.

Assessment

Checkout Quiz mengecek pemahaman keyboard event, coordinate X/Y, forever, if, touching, hide/show, pick random, dan reset.

Jika siswa bingung, arahkan mereka kembali ke code final dan test case. Bantuan guru sebaiknya pada cara membaca alur, bukan memberi jawaban quiz.

Ringkasan Konsep

Sesi 19 menggabungkan konsep sebelumnya menjadi game mechanic. Event keyboard mengontrol pemain, forever menjalankan gerakan terus-menerus, dan if menentukan respons berdasarkan kondisi.

Kemampuan membaca alur ini penting karena project game akan semakin kompleks jika nanti ditambah skor, level, atau suara.

Glosarium

Glosarium ini membantu siswa membaca ulang materi secara mandiri. Istilah paling penting pada sesi ini adalah game mechanic dan touching.

Jika siswa bisa menjelaskan istilah ini dengan contoh dari project, berarti mereka tidak sekadar menghafal block.

Penutup

Di sesi ini, siswa belajar bahwa game bekerja karena ada aturan yang jelas. Jika tombol ditekan, Mangkuk bergerak. Jika Koin tertangkap, Koin muncul lagi. Jika Koin terlewat, Koin juga muncul lagi.

Konsep ini menjadi dasar untuk project game yang lebih lengkap. Siswa sudah punya fondasi event, loop, sensing, condition, dan reset.
