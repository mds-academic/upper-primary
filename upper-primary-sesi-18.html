Repeat vs Forever

repeat

Dipakai kalau jumlah pengulangannya sudah ditentukan.

repeat 25 berarti isi loop dijalankan 25 kali.

forever

Dipakai kalau perintah perlu terus berjalan selama project aktif.

Berhenti ketika tombol Stop ditekan.

Contoh: tepuk tangan 5 kali = repeat. Jam berdetak terus = forever.

Selamat datang di Sesi 18

Sesi ini fokus pada loop, yaitu cara membuat perintah di Scratch berjalan berulang. Project-nya adalah Pabrik Roti, jadi gerakan Roti dibuat seperti proses produksi yang terus berjalan.

Kita akan mulai dari percobaan sederhana menggunakan repeat, lalu naik ke versi akhir menggunakan forever dan if. Siswa perlu paham bahwa program bukan hanya membuat Roti bergerak, tetapi juga tahu kapan Roti harus kembali ke posisi awal.

Target Belajar

Di akhir sesi, siswa diharapkan bisa menjelaskan perbedaan repeat dan forever, membuat sprite bergerak menggunakan change y by, dan melakukan reset posisi dengan go to x: y:.

Quick check menegaskan konsep penting sejak awal: repeat digunakan jika jumlah pengulangannya sudah jelas, sedangkan forever digunakan jika perintah perlu terus berjalan selama project aktif.

Persiapan

Pastikan siswa membuka project yang benar sebelum mulai. Sesi ini banyak membandingkan hasil percobaan, jadi lebih baik siswa bekerja di copy project agar versi awal tetap aman.

Keamanan digital tetap disisipkan secara ringan: siswa tidak perlu memakai data pribadi dan tidak perlu membuka tab lain yang tidak terkait project. Fokusnya adalah Scratch dan logika gerak sprite.

Masalah Project

Kalau Roti hanya turun satu kali, project belum terasa seperti proses pabrik. Kita butuh pola: mulai di atas, turun, sampai bawah, kembali lagi ke atas, lalu turun lagi.

Pola seperti ini cocok untuk belajar loop dan kondisi. Loop membuat gerakan terjadi berulang, sedangkan kondisi membantu program memutuskan kapan Roti harus di-reset ke posisi awal.

Sumbu Y

Materi ini membutuhkan pemahaman koordinat dasar. Nilai change y by -10 membuat sprite turun karena angka Y dikurangi.

Jika nanti Roti bergerak ke arah yang salah, salah satu bug yang paling mungkin adalah tanda positif/negatif pada change y by. Ini perlu sering diingatkan karena siswa mudah tertukar antara X dan Y.

Loop

Loop membuat code lebih ringkas dan mudah dibaca. Daripada menulis change y by -10 berkali-kali, siswa bisa memasukkannya ke dalam block repeat atau forever.

Tekankan bahwa block yang berada di dalam bentuk C akan ikut diulang. Jika sebuah block ditaruh di luar loop, block itu tidak ikut berulang.

Repeat dan Forever

Repeat cocok untuk aktivitas yang punya batas jumlah, misalnya bergerak 10 kali. Setelah jumlah pengulangan selesai, program lanjut atau berhenti sesuai block berikutnya.

Forever cocok untuk aktivitas yang harus terus diperiksa atau terus berjalan. Dalam project Pabrik Roti, proses produksi akan dibuat terus berjalan, jadi versi finalnya menggunakan forever.

Fungsi Wait

Tanpa wait, gerakan bisa terlihat terlalu cepat karena Scratch menjalankan perintah berulang dengan sangat cepat. wait memberi jeda agar mata manusia dapat mengikuti gerak sprite.

Nilai wait yang lebih besar membuat jeda lebih lama, sehingga gerakan terlihat lebih lambat. Dalam sample project, Roti memakai wait 0.1 seconds.

Memilih Loop

Aktivitas mini ini membantu siswa tidak hanya menghafal nama block, tetapi memahami kapan block digunakan. Pertanyaan kuncinya: apakah aktivitas punya jumlah pengulangan yang jelas?

Jika ada jumlah seperti 5 kali atau 10 kali, gunakan repeat. Jika harus terus berjalan selama project aktif, gunakan forever.

Percobaan Repeat

Percobaan ini penting karena siswa melihat sendiri bahwa repeat tidak berjalan selamanya. Setelah isi loop dijalankan sesuai jumlahnya, loop selesai.

Jika Roti berhenti di bawah, itu bukan bug. Itu justru bukti bahwa repeat bekerja sesuai konsep. Yang belum ada adalah aturan untuk membuat Roti kembali ke atas dan terus berjalan.

Membaca Hasil Repeat

Slide ini membantu siswa menyimpulkan percobaan. Repeat 25 bukan berarti sprite terus berjalan. Artinya sprite menjalankan isi loop 25 kali lalu selesai.

Kesimpulan ini menjadi jembatan ke forever. Kita tidak langsung memakai forever karena siswa perlu melihat dulu perbedaannya.

Forever

Forever membuat isi loop dijalankan terus selama project aktif. Untuk Pabrik Roti, ini membuat Roti terus bergerak turun.

Namun, jika hanya memakai forever dan gerak turun, Roti bisa keluar dari Stage. Karena itu kita butuh kondisi untuk memeriksa kapan Roti sudah mencapai bagian bawah.

Kenapa Butuh If?

Forever saja belum cukup. Program perlu tahu kapan harus mengambil tindakan. Di sinilah if digunakan.

Dalam modul, konsep yang dipakai adalah mengecek apakah y position sudah melewati batas bawah. Jika iya, sprite dikembalikan ke posisi awal.

Y Position

y position dapat dipakai seperti sensor sederhana untuk mengetahui posisi sprite. Saat Roti turun, nilai Y berubah menjadi lebih kecil.

Dalam lesson plan, guru boleh menggunakan konsep y position < batas bawah. Di file sample, kondisi yang dipakai adalah y position = -115. Keduanya tetap mengajarkan ide yang sama: program membaca posisi untuk menentukan waktu reset.

Reset di Sample Project

Sample project Sesi 18 memakai urutan visual yang cukup lengkap. Saat Roti sampai posisi bawah, Roti melakukan glide, lalu hide, menunggu sebentar, kembali ke atas dengan go to, lalu show.

Inti konsepnya tetap sama: setelah mencapai batas, sprite dikembalikan ke posisi awal agar gerakan bisa berulang.

Code Final

Slide ini merangkum alur code final dari sample project. Perhatikan bahwa if berada di dalam forever, sehingga posisi Roti terus diperiksa.

Jika if ditaruh di luar forever, program hanya mengecek kondisi satu kali. Itu membuat reset mudah gagal karena Roti belum sampai bawah saat pengecekan terjadi.

Trace Manual

Tracing membantu siswa membaca program tanpa harus langsung mengubah block. Mereka mengikuti alur: mulai dari atas, bergerak turun, mengecek posisi, lalu reset.

Kebiasaan tracing penting untuk debugging. Jika output salah, siswa bisa mencari tahap pertama yang tidak berjalan sesuai rencana.

Project Sprint A

Bagian ini mengikuti lesson plan: siswa mencoba repeat dulu. Output yang benar adalah Roti turun lalu berhenti setelah jumlah pengulangan selesai.

Guru perlu menghindari siswa langsung loncat ke forever. Percobaan repeat memberi bukti konkret bahwa loop bisa punya batas.

Project Sprint B

Bagian ini adalah inti project final. Siswa menambahkan forever, if, dan reset posisi. Pastikan if berada di dalam forever.

Jika menggunakan sample project, ada tambahan hide dan show. Pastikan siswa tidak lupa show, karena tanpa itu Roti bisa tidak terlihat lagi.

Testing

Testing harus mencakup dua versi: repeat dan forever. Pada versi repeat, output yang dicari adalah gerakan yang berhenti. Pada versi forever, output yang dicari adalah siklus turun-reset yang terus berjalan.

Test terakhir, Stop lalu Green Flag, membantu memastikan project bisa dijalankan ulang dari kondisi awal dan tidak bergantung pada posisi terakhir sprite.

Debugging

Debugging diarahkan berdasarkan gejala. Jika arah gerak salah, cek angka pada change y by. Jika reset tidak terjadi, cek posisi if dan kondisi y.

Jika Roti menghilang selamanya, kemungkinan besar hide tidak diikuti show. Siswa sebaiknya mengganti satu hal lalu test ulang, bukan menghapus banyak block sekaligus.

Makna Otomatis

Otomatis bukan berarti project punya robot sungguhan. Otomatis berarti program punya aturan yang berjalan sendiri setelah dimulai.

Dalam project ini, aturannya adalah: Roti turun, posisi dicek, lalu Roti kembali ke posisi awal. Pola ini menguatkan konsep sequence, loop, dan condition.

Extension Challenge

Challenge memberi ruang untuk siswa cepat tanpa mengubah tujuan utama. Namun, pastikan mereka menyelesaikan dan menguji mechanic utama terlebih dahulu.

Setelah membuat perubahan, testing perlu diulang. Fitur tambahan yang merusak loop utama perlu diperbaiki atau dikembalikan.

Penyimpanan

Siswa perlu menyimpan project setelah versi final stabil. Jika project belum diuji, guru akan sulit membedakan apakah file belum selesai atau ada bug tertentu.

Jika pengumpulan dilakukan lewat LMS, arahkan siswa mengikuti instruksi guru. Bukti belajar utama adalah project Roti yang turun, reset, dan dapat diulang.

Refleksi

Refleksi membantu siswa menyusun pemahaman sendiri. Mereka tidak perlu menjawab panjang, tetapi perlu menyebutkan alasan.

Jawaban yang baik menunjukkan hubungan antara tujuan dan block: repeat untuk jumlah tertentu, forever untuk proses terus berjalan, dan debugging dilakukan berdasarkan gejala project.

Assessment

Checkout Quiz mengecek konsep loop, arah gerak pada sumbu Y, fungsi wait, kondisi posisi, dan reset sprite.

Jika siswa masih bingung, arahkan mereka melihat kembali code final dan test case. Hindari memberi jawaban langsung; bantu siswa membaca alur logikanya.

Ringkasan Konsep

Empat block utama sesi ini membentuk mechanic Pabrik Roti: forever untuk pengulangan, change y by untuk gerak turun, if untuk cek batas, dan go to untuk reset.

Konsep ini akan dipakai lagi pada sesi berikutnya saat membuat game. Bedanya, nanti sprite bukan hanya bergerak otomatis, tetapi juga bereaksi terhadap keyboard dan sentuhan.

Glosarium

Glosarium membantu siswa membaca ulang materi secara mandiri. Jika siswa lupa istilah, mereka bisa kembali ke slide ini tanpa harus menebak dari bentuk block.

Istilah yang paling penting adalah loop dan reset, karena keduanya menjadi dasar mechanic game pada Sesi 19.

Penutup

Sesi 18 menyiapkan siswa untuk game mechanic. Mereka sudah melihat bahwa loop bukan hanya untuk mengulang gerakan, tetapi juga bisa digabung dengan kondisi dan reset.

Di sesi berikutnya, ide yang sama dipakai untuk membuat Koin jatuh, terdeteksi saat tertangkap, dan kembali ke atas agar game dapat terus dimainkan.
