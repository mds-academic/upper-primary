Gambaran Sesi

Sesi ini mengajak siswa memakai Scratch untuk membuat keputusan dua cabang. Project tidak langsung menyuruh user membeli barang, tetapi membantu membandingkan angka: saldo dan harga.

Fokus coding hari ini adalah urutan input, penyimpanan jawaban ke variable, lalu percabangan memakai if-then-else. Dari sisi finansial, siswa diajak ingat bahwa uang cukup bukan berarti barang harus langsung dibeli.

Output akhir

Project bertanya saldo, bertanya harga buku, lalu menampilkan pesan: saldo belum cukup atau saldo cukup sambil tetap mempertimbangkan kebutuhan dan keinginan.

Tujuan Belajar

Targetnya bukan hanya siswa bisa meniru blok, tetapi juga memahami mengapa bloknya disusun seperti itu. Mereka perlu tahu peran ask and wait, answer, variable saldo, operator <, dan percabangan.

Pada akhir sesi, siswa diharapkan bisa menjelaskan bahwa program mengecek saldo dengan membandingkan angka, lalu memilih salah satu pesan. Siswa juga perlu bisa memberi alasan sederhana saat membahas kebutuhan dan keinginan.

Persiapan Kelas

Siswa Upper Primary biasanya sudah bisa mengikuti instruksi teknis mandiri, tetapi tetap perlu checkpoint singkat. Pastikan mereka membuka file yang benar dan tidak mulai mengubah banyak hal sebelum instruksi utama dimulai.

Tekankan bahwa nominal pada project adalah data simulasi. Tujuannya belajar logika dan kebiasaan mengambil keputusan, bukan membagikan informasi keuangan pribadi.

Konteks Finansial

Mulai dari konteks yang dekat dengan siswa: ingin membeli buku atau barang sekolah. Di sini, siswa diajak membedakan dua hal: apakah uangnya cukup, dan apakah barang itu memang perlu dibeli.

Project Scratch membantu bagian perhitungan sederhana. Namun keputusan akhir tetap perlu memakai pertimbangan manusia: kebutuhan, keinginan, dan prioritas.

Pesan penting

Saldo cukup tidak selalu berarti harus membeli. Bisa saja uangnya lebih baik disimpan untuk kebutuhan lain.

Prioritas Finansial

Slide ini menguatkan literasi finansial: program bisa membantu menghitung atau membandingkan, tetapi tidak menggantikan pertimbangan. Anak perlu belajar bahwa kebutuhan biasanya didahulukan dibanding keinginan.

Jangan membuat keinginan terdengar “salah”. Yang ditekankan adalah urutan prioritas dan kebiasaan berpikir sebelum membeli.

Menghubungkan IF dengan Keputusan

Sebelum masuk ke blok Scratch, siswa perlu memahami pola bahasa sederhana: kalau kondisi terjadi, maka aksi tertentu dilakukan. Dalam coding, kondisi akan dicek sebagai benar atau salah.

Untuk project ini, kondisi utamanya adalah saldo < harga. Kalau benar, saldo belum cukup. Kalau salah, saldo cukup karena saldo sama atau lebih besar dari harga.

True / False

Operator < menghasilkan jawaban benar atau salah. Ini penting karena if-then-else hanya menjalankan salah satu cabang.

Kondisi saldo < harga berarti “apakah saldo lebih kecil dari harga?” Kalau iya, cabang then berjalan. Kalau tidak, cabang else berjalan.

Nilai batas

Jika saldo 7.000 dan harga 7.000, kondisi 7000 < 7000 adalah salah. Jadi saldo dianggap cukup.

Fungsi ask and wait

Blok ask and wait digunakan ketika program membutuhkan input dari user. Setelah user menjawab, Scratch menyimpan jawaban itu sementara di blok answer.

Karena project ini bertanya dua kali, siswa perlu paham bahwa answer akan berubah setiap kali pertanyaan baru dijawab.

Kenapa Perlu Variable?

Scratch tidak otomatis menyimpan semua jawaban lama. Setelah pertanyaan kedua dijawab, answer berisi jawaban kedua, yaitu harga buku.

Karena itu, jawaban pertama perlu dipindahkan ke variable saldo. Tanpa langkah ini, program akan kesulitan membandingkan saldo dengan harga.

Membaca Variable

Untuk siswa, analogikan variable sebagai kotak penyimpanan. Kita menaruh saldo ke dalam kotak bernama saldo, lalu nanti kotak itu dibuka lagi saat membandingkan dengan harga.

Urutan blok sangat penting. set saldo to answer harus berada setelah pertanyaan saldo dan sebelum pertanyaan harga.

Membaca Alur Sebelum Coding

Flowchart membantu siswa melihat urutan kerja program tanpa terganggu bentuk blok. Bagian paling penting adalah: input pertama disimpan, input kedua dibandingkan, lalu program memilih pesan.

Jika siswa nanti mengalami bug, flowchart ini bisa dipakai sebagai peta untuk tracing dari atas ke bawah.

Aktivitas Mini

Prediksi manual membuat siswa lebih siap saat testing. Mereka tidak hanya menjalankan project, tetapi tahu apa hasil yang seharusnya muncul.

Pastikan ada tiga kondisi: saldo lebih besar, saldo lebih kecil, dan saldo sama dengan harga. Kondisi saldo sama penting karena sering menjadi sumber miskonsepsi.

Persiapan Guided Build

Sebelum menyusun blok, siswa perlu memilih sprite yang benar dan membuat variable saldo. Jika variable belum dibuat, blok set saldo to answer tidak akan tersedia.

Gunakan checkpoint ini untuk menghindari bug dasar sebelum masuk ke percabangan.

Bagian A

Bagian awal dimulai dari event when green flag clicked. Setelah itu, program menampilkan pertanyaan saldo.

Minta siswa mengetik angka tanpa titik atau “Rp” agar mudah dibandingkan oleh Scratch. Contoh: ketik 10000, bukan Rp10.000.

Bagian B

Ini checkpoint paling penting. Setelah siswa menjawab saldo, answer berisi saldo. Segera simpan ke variable saldo.

Jika blok ini diletakkan setelah pertanyaan harga, maka variable saldo justru berisi harga. Itu akan membuat hasil perbandingan salah.

Bagian C

Setelah pertanyaan harga dijawab, answer sekarang berisi harga buku. Ini memang yang kita butuhkan untuk dibandingkan dengan variable saldo.

Siswa perlu bisa menyebutkan data mana yang disimpan di mana: saldo untuk jawaban pertama, answer untuk harga dari jawaban kedua.

Bagian D

Kondisi memakai saldo < answer karena setelah pertanyaan kedua, answer berisi harga buku. Jadi program sedang bertanya: “apakah saldo lebih kecil dari harga?”

Jangan dibalik menjadi answer < saldo, karena artinya berubah menjadi “apakah harga lebih kecil dari saldo?” dan cabang pesannya bisa tertukar.

Bagian E

Cabang then dipakai untuk kondisi benar. Dalam project ini, kondisi benar berarti saldo belum cukup.

Pesan “Ayo menabung dulu” memberi arahan finansial yang positif. Siswa tidak hanya tahu uangnya kurang, tetapi juga tahu tindakan yang lebih bijak.

Bagian F

Cabang else berjalan saat kondisi saldo < harga salah. Artinya saldo sama dengan harga atau lebih besar dari harga.

Pesan cukup sengaja tidak berbunyi “langsung beli”. Di sesi ini, siswa belajar bahwa cukup secara angka tetap perlu dipertimbangkan secara prioritas.

Answer Key Coding

Ini adalah bentuk final script utama. Jika siswa mengalami kesulitan, pecah pengerjaan menjadi tiga bagian: input saldo, input harga, lalu percabangan.

Checkpoint cepat

1. Ada dua blok ask and wait.
2. Ada set saldo to answer setelah pertanyaan saldo.
3. Kondisi memakai saldo < answer.
4. Pesan then dan else berbeda.

Tracing

Tracing berarti membaca program langkah demi langkah. Ini membantu siswa mencari sumber bug tanpa menebak-nebak.

Ajarkan pola sederhana: input pertama → simpan ke variable → input kedua → bandingkan → lihat cabang yang berjalan.

Testing Tiga Kondisi

Testing wajib mencakup dua cabang dan satu nilai batas. Jika hanya mencoba saldo cukup, siswa belum membuktikan cabang then bekerja. Jika hanya mencoba saldo kurang, siswa belum membuktikan cabang else bekerja.

Kasus saldo sama dengan harga penting karena menguji pemahaman operator <. Sama dengan bukan lebih kecil, sehingga masuk ke else.

Checkpoint Project

Checklist ini membantu siswa memastikan project bukan hanya “jalan”, tetapi juga sesuai logika. Untuk project percabangan, semua cabang perlu diuji.

Jika ada hasil yang salah, jangan langsung menghapus semua script. Gunakan debugging slide berikutnya agar siswa mengecek bagian yang paling mungkin bermasalah.

Debugging

Debugging diarahkan berdasarkan gejala. Jika saldo tidak tersimpan, cek variable. Jika hasil terbalik, cek operator atau cabang. Jika pesan muncul tidak sesuai, cek posisi blok say.

Tekankan kebiasaan mengganti satu hal, lalu test ulang. Jangan mengganti banyak blok sekaligus karena sumber bug jadi sulit ditemukan.

Extension

Challenge menjaga siswa cepat tetap tertantang tanpa mengubah tujuan utama. Tambahan ekspresi atau kalimat boleh dilakukan setelah script utama benar.

Ingatkan siswa bahwa setelah menambah fitur, testing perlu diulang. Fitur tambahan tidak boleh merusak hasil utama.

Penyimpanan

Setelah project stabil, siswa menyimpan dan mengumpulkan sesuai instruksi guru atau LMS. Untuk sesi ini, bukti belajar yang dicari adalah project yang bisa menerima dua input dan memberi respons sesuai kondisi.

Jika siswa mengumpulkan file yang belum diuji, guru akan lebih sulit menilai apakah bug terjadi karena coding atau karena file belum selesai.

Refleksi

Refleksi membantu siswa menghubungkan coding dengan konsep finansial. Jawaban tidak perlu panjang, tetapi harus menunjukkan pemahaman alur dan alasan.

Contoh jawaban yang diharapkan: saldo perlu disimpan karena answer berubah; saldo cukup belum tentu harus beli karena perlu melihat kebutuhan dan keinginan.

Penutup
