Selamat datang di misi hari ini!

Kiko ingin membuat project Scratch. Tapi sebelum menyusun blok, Kiko perlu tahu dulu langkah-langkahnya.

Kalau semua ide langsung dikerjakan sekaligus, project bisa jadi membingungkan. Karena itu, game creator biasanya membuat rencana dulu.

Misi hari ini: membuat flowchart sederhana, lalu mengubahnya menjadi project Scratch kecil.

Apa yang akan kamu kuasai?

Setelah sesi ini, kamu diharapkan bisa menjelaskan urutan project dengan lebih rapi.

  • Memecah project menjadi beberapa langkah kecil.
  • Menentukan urutan langkah yang benar.
  • Mengenali pola langkah yang sering muncul.
  • Membaca flowchart sederhana.
  • Mengubah flowchart menjadi susunan blok Scratch.

Rencana membantu kita fokus

Saat membuat project, ide bisa terasa banyak sekali. Rencana membantu kita memilih langkah yang perlu dikerjakan dulu.

Di Scratch, blok dijalankan dari atas ke bawah. Jadi urutan blok sangat penting.

Kalau sprite diminta bicara sebelum muncul, pemain mungkin bingung karena aksi pertamanya belum jelas.

Decomposition itu seperti membagi pekerjaan

Membuat game Scratch bukan satu langkah saja. Kita bisa membaginya menjadi bagian kecil, misalnya memilih sprite, memilih backdrop, membuat gerakan, menambahkan dialog, lalu mengetes hasilnya.

Dengan cara ini, project terasa lebih ringan dan mudah diselesaikan.

Coba pecah project kecil

Tidak semua hal termasuk langkah project. Fokuslah pada hal yang benar-benar dibutuhkan agar project berjalan.

Project kecil biasanya membutuhkan: aset, kalimat, susunan blok, dan testing.

Ingat: pilih langkah yang bisa langsung membantu project selesai.

Urutan membuat hasil berbeda

Sequence berarti langkah-langkah disusun dengan urutan yang masuk akal.

Contoh sederhana: saat membuat roti, kita menyiapkan bahan dulu sebelum memanggang. Kalau urutannya terbalik, hasilnya tidak sesuai.

Di Scratch, urutan blok juga penting karena program membaca blok dari atas ke bawah.

Dari roti ke coding

Aktivitas ini melatih cara berpikir programmer: pekerjaan harus punya urutan yang jelas.

Setelah kamu bisa menyusun langkah roti, kita akan memakai cara yang sama untuk menyusun langkah project Scratch.

Pola membuat kita lebih cepat memahami masalah

Pattern berarti ada langkah yang mirip atau berulang. Dalam coding, pola sering muncul saat testing.

Misalnya: coba project → temukan bug → perbaiki → coba lagi. Pola ini bisa terjadi berkali-kali sampai project berhasil.

Bug bukan tanda gagal. Bug adalah tanda bahwa ada bagian yang perlu diperiksa.

Cara menemukan pola

Tanyakan pada dirimu: “Apakah langkah ini terjadi lebih dari satu kali?” Kalau iya, mungkin itu sebuah pattern.

Programmer yang bisa melihat pola biasanya lebih mudah memperbaiki project dan membuat kode yang rapi.

Flowchart membuat langkah terlihat jelas

Flowchart membantu kita melihat alur sebelum membuat kode. Bentuknya seperti peta kecil yang menunjukkan apa yang terjadi dari awal sampai akhir.

Dengan flowchart, teman atau guru juga bisa memahami rencana project kita lebih cepat.

Tidak perlu menghafal semuanya sekaligus

Hari ini kamu cukup mengenal simbol dasar: mulai, proses, panah, dan selesai.

Simbol keputusan akan dipakai lebih banyak saat kita belajar kondisi seperti if-then.

Flowchart sebelum kode

Di project utama, flowchart ini akan menjadi panduan saat menyusun blok Scratch.

Kalau flowchart sudah rapi, kamu tinggal mencari blok yang sesuai untuk setiap langkah.

Catatan: “Ganti costume” tetap bagian dari aksi sebelum project selesai.

Project Scratch sesi ini

Project hari ini sederhana, tetapi penting. Kamu akan melatih cara menyusun alur yang rapi.

Hasil minimum: satu sprite dapat muncul, bergerak, berbicara, dan berganti costume sesuai urutan.

Kalau kamu belum menemukan sprite dengan dua costume, pilih sprite lain atau duplikasi costume di tab Costumes.

Dari flowchart ke Scratch

Setiap kotak pada flowchart bisa dihubungkan dengan blok Scratch.

  • Mulai → when green flag clicked
  • Show → sprite muncul di Stage
  • Move → sprite bergerak
  • Say → sprite menyampaikan dialog
  • Next Costume → sprite berganti tampilan

Sebelum menyusun blok

Pastikan project sudah siap agar kamu tidak bolak-balik terlalu sering saat coding.

Nama project penting supaya file kamu mudah ditemukan lagi nanti.

Jika sprite hanya punya satu costume, blok next costume tidak akan terlihat jelas hasilnya.

Event pertama: Green Flag

Blok when green flag clicked menjadi tanda mulai. Semua blok yang tersambung di bawahnya akan dijalankan dari atas ke bawah.

Blok show memastikan sprite terlihat saat project dimulai.

Blok move steps membuat sprite bergerak sesuai arah hadapnya.

Jika arah sprite berubah, arah geraknya juga bisa berubah. Karena itu, jalankan project untuk melihat hasilnya.

Dialog harus jelas terbaca

Blok say for seconds membuat dialog tampil selama beberapa detik.

Costume membuat perubahan terlihat

Blok next costume membuat sprite berganti tampilan ke costume berikutnya.

Ini membuat project terasa lebih hidup, walaupun projectnya sederhana.

Perhatikan urutannya

Simulasi ini menunjukkan hasil dari sequence: muncul, bergerak, berbicara, lalu berganti costume.

Di Scratch, hasilnya akan mengikuti susunan blok yang kamu buat.

Setelah menambah satu blok, coba tekan Green Flag. Dengan begitu, kamu tahu bagian mana yang sudah berhasil.

Debugging adalah kebiasaan penting

Debugging berarti mencari dan memperbaiki kesalahan pada project.

Ketika project belum berjalan sesuai rencana, jangan langsung panik. Cek satu per satu: event, urutan blok, isi teks, angka, dan costume.

Detektif kode yang baik tidak menebak asal-asalan. Ia mencari penyebab dari masalahnya.

Output minimum

Misi berhasil jika projectmu dapat dijalankan dari awal sampai akhir dengan urutan yang benar.

Gunakan checklist di kiri untuk memeriksa projectmu sendiri sebelum meminta bantuan guru.

Target minimum: satu sprite menjalankan semua langkah sesuai flowchart.

Berpikir sebelum membuat

Flowchart tidak menggantikan coding. Flowchart membantu kita membuat rencana agar coding lebih rapi.

Semakin jelas rencananya, semakin mudah kamu menyusun blok dan menemukan bug.

Saat membaca flowchart teman, coba tanyakan: “Apakah urutannya sudah masuk akal?”
